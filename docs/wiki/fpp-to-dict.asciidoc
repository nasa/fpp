This tool writes JSON dictionaries corresponding to F Prime systems and
deployment topologies.

*Options:*

. `-d` _dir_: Set the output directory to _dir_.
If this option is not present, then the output directory is
the current directory.

.  `-i` _files_: Import _files_.
The definitions in these files are part of the FPP model, but they do not cause 
any code to be generated.

. `-f` _framework version_: Specify the framework version.

. `-p` _project version_: Specify the project version.

. `-l` _library versions_: Specify the versions of libraries used in the project.

*Input:*

. A list _fl_tr_ of files to translate: either the single file _stdin_ or a list of 
files specified on the command line.

. A list _fl_i_ of files to import, specified as arguments to the `-i` option.

*Output:*

. A set of `.json` files, written to the output directory.

*Procedure:*

. Parse each of the files in the concatenation of _fl_tr_ and _fl_i_, 
  generating a list _tul_ of translation units.

. Perform https://github.com/nasa/fpp/wiki/Checking-Semantics[semantic 
  checking] on _tul_, generating a new list _tul'_.

. Let _tul_tr'_ be the set of translation units in _tul'_ corresponding
to _fl_tr_.

. If _tul_tr'_ contains a system definition _S_, then do the following:

.. Let _D_ be the dictionary for the topology referred to in _S_.

.. Generate the JSON output for _D_.

*Compatibility notes:*

* Topology dictionaries are generated for backwards compatibility
with the F Prime tools.
When the F Prime tools are updated to use the system dictionary,
we will remove this code generation.

* The `-i` option imports dependency files for analysis
but not code generation.
This option is retained for backwards compatibility
with older versions of `fpp-to-dict` that generated dictionaries
for all topologies, including subtopologies of the deployment
topology.
`fpp-to-dict` now generates dictionaries
for systems and deployment topologies only, and these
top-level definitions should not appear in dependency files.
Therefore, it is safe to include the dependency files as
part of the main input to the tool, as with `fpp-check`.
