=== Template Expansion Specifiers

A *template expansion specifier* names a 
<<Definitions_Module-Template-Definitions,module template definition>>
and specifies arguments for the parameters of the template.
During <<Expansion-of-Templates,template expansion>>, it generates the definitions specified 
by the template and the arguments.

==== Syntax

`expand`
<<Scoping-of-Names_Qualified-Identifiers,_qual-ident_>>
_[_
`(` _template-arg-list_ `)`
_]_
_[_
`{` _module-member-sequence_ `}`
_]_

_template-arg-list_ is an
<<Element-Sequences,element sequence>> in
which the elements are template arguments, and
the terminating punctuation is a comma.

Each template argument is one of the following:

. A *constant template argument* `constant` <<Expressions,_expression_>>

. A *port interface instance template argument*
`instance` <<Scoping-of-Names_Qualified-Identifiers,_qual-ident_>>

. A *type template argument* `type` <<Type-Names,_type-name_>>

_module-member-sequence_ is the same as for a
<<Definitions_Module-Definitions_Syntax,module definition>>.

The optional module member list represents the result of
<<Expansion-of-Templates,expanding the template>>.
If a template expansion specifier has a module member
list, then it is called an *expanded template*.
Otherwise it is called an *unexpanded template*.

==== Semantics

. The qualified identifier must
<<Scoping-of-Names_Resolution-of-Qualified-Identifiers,refer to>>
the definition of a
<<Definitions_Module-Template-Definitions,module template _T_>>.

. The number of template arguments must match the number of template
parameters in _T_.
If there are no parameters, then the argument list may be omitted.

. For each template parameter _p_, let _A_ be the corresponding argument.

.. If _p_ is a constant template parameter, then _A_ must be a constant
template argument. The expression in _A_ must <<Evaluation,evaluate>>
to a value that is <<Evaluation_Type-Conversion,convertible to>> the type 
specified in _p_.

.. If _p_ is a port interface instance template parameter, then _A_
must be a port interface instance template argument.
The qualified identifier in _A_ must
<<Scoping-of-Names_Resolution-of-Qualified-Identifiers,refer to>>
a <<Ports_Port-Interface-Instances,port interface instance>> _N_.
The port interface referred to in _p_ must be a
<<Ports_Sub-Interfaces,sub-interface>> of the <<Ports_Port-Interfaces,port 
interface of _N_>>.

.. If _p_ is a type template parameter, then _A_ must be a type
template argument.

.. Within the <<Expansion-of-Templates,expansion>> generated by the
   template expansion specifier, the pair stem:[B = (p, A)] is
   <<Scoping-of-Names_Resolution-of-Identifiers_Inside-an-Expanded-Template,in 
   scope as a definition>> and is called a <<Definitions,bound parameter definition>>.
   There are three kinds of bound parameter definitions:

... When _p_ is a constant template parameter, _B_ is called a
    *constant parameter definition*.

... When _p_ is a port interface instance template parameter, _B_
    is called a *port interface instance parameter definition*.

... When _p_ is a type template parameter, _B_
    is called a *type parameter definition*.

. If _module-member-sequence_ is present, then

.. _module-member-sequence_ must not transitively contain any 
<<Definitions_Module-Template-Definitions,module
template definitions>> or template expansion specifiers.
This rule ensures that the syntax of _module-member-sequence_ could
be produced by expanding some template.

.. _module-member-sequence_ must not transitively contain any
<<Definitions_Topology-Definitions,deployment topology definitions>> or
<<Definitions_System-Definitions,system definitions>>.

.. _module-member-sequence_ is not required to conform to the syntax produced 
by expanding the template referred to in the specifier.

.. All the definitions and uses inside _module-member-sequence_ are
semantically analyzed in the same way as if _module-member-sequence_ had been
produced by <<Expansion-of-Templates,template expansion>>.

==== Examples

[source,fpp]
----
port P

@ A basic template parameterizing an interface port count
module template T(constant numPorts: U32) {

  interface I {
    output port p: [numPorts] P
  }

  passive component C {
    import I
  }

}

@ Instantiate the template giving the parameters concrete values
module M {

  expand T(constant 30)
  # Bound parameter definition (constant numPorts: U32, 30)
  # Global definition interface I { output port p: [numPorts] P }
  # Global definition passive component C { output port p: [numPorts] P }

}

----
