=== Framework Definitions

Several definitions are used specially by the F Prime framework.
These are called *framework definitions.*

==== Constant Definitions

The table below lists the framework constant definitions.
Each row in the table has the following meaning:

. The row provides a qualified name _N_ and a set of rules _R_.

. If the model contains a 
<<Definitions_Constant-Definitions,constant definition>> _D_ with 
<<Scoping-of-Names_Names-of-Definitions,qualified name>> _N_,
then _D_ must have the following properties:

.. Each qualified identifier that is a prefix of the
name _N_, but not the name itself, must
<<Scoping-of-Names_Resolution-of-Qualified-Identifiers,refer to>> a
<<Definitions_Module-Definitions,module definition>>.
For example, the definition _D_  may not appear inside a component
or state machine.

.. The definition _D_ must conform to the rules _R_.

The rules use the following terms:

* An *integer constant* is a <<Definitions_Constant-Definitions,constant definition>>
whose <<Types_Underlying-Types,underlying type>> is an
  <<Types_Internal-Types_Integer-Types,integer type>>.

* A *nonnegative integer constant* is an integer constant
  whose value is greater than or equal to zero.

* A *positive integer constant* is an integer constant
  whose value is greater than zero.

* A *string size constant* is an integer constant whose value is a
  valid <<Types_String-Types,string size>>.

==== Buffer Sizes

The F Prime framework serializes the arguments of commands and
events and the values of parameters and telemetry channels into
buffers of fixed size.
The table below lists the data serialized for each kind of
<<Specifiers,specifier>> and the framework constant _B_ that specifies the
size of the buffer.

|===
|Specifier|Serialized Data|_B_

|<<Specifiers_Command-Specifiers,Command specifier>>
|The command parameters
|`FW_CMD_ARG_BUFFER_MAX_SIZE`

|<<Specifiers_Event-Specifiers,Event specifier>>
|The event parameters
|`FW_LOG_BUFFER_MAX_SIZE`

|<<Specifiers_Parameter-Specifiers,Parameter specifier>>
|The parameter value
|`FW_PARAM_BUFFER_MAX_SIZE`

|<<Specifiers_Telemetry-Channel-Specifiers,Telemetry channel specifier>>
|The channel value
|`FW_TLM_BUFFER_MAX_SIZE`

|===

If the model contains a framework constant definition _B_ with value _b_,
then for each specifier of the corresponding kind,
the *minimum serialized size* of the serialized data must be at most _b_.
The minimum serialized size of the serialized data is the sum of the
minimum serialized sizes of its types, where the minimum serialized size
of a type _T_ is defined as follows:

* If the <<Types_Underlying-Types,underlying type>> of _T_ is a
<<Types_String-Types,string type>>, then the minimum serialized size
of _T_ is the serialized size of the framework type `FwSizeStoreType`.
This is the size of an empty string.

* If the underlying type of _T_ is an array type with size _n_ and
element type _T'_, then the minimum serialized size of _T_ is _n_ times
the minimum serialized size of _T'_.

* If the underlying type of _T_ is a struct type, then the minimum
serialized size of _T_ is the sum of the minimum serialized sizes of
its members, where a member with a size _n_ counts _n_ times.

* Otherwise the minimum serialized size of _T_ is the
<<Types_Serialized-Sizes,serialized size>> of _T_.

So the check reports an error only when no value of the serialized
data can fit in the buffer.
The minimum serialized size does not include data that depends on
the configuration of the F Prime C++ framework, such as the
argument sizes stored in an event when `FW_AMPCS_COMPATIBLE` is enabled.
