== Type Names

*Type names* are the syntactic names of
<<Types,types>>.
In some cases, e.g., `U32`, there is a one-to-one correspondence
between type names and types.
In other cases, e.g., array types, there is no one-to-one correspondence.
For example, depending on the enclosing scope, the name
`a.b` and the name `b` may refer to the same array type.

=== Primitive Integer Type Names

*Primitive integer type names* are the names of the
<<Types_Primitive-Integer-Types,primitive integer types>>.
There are two kinds of primitive
integer types: unsigned integer types and signed integer types.

* The names of the unsigned integer types are `U8`, `U16`, `U32`, and `U64`.
The `U` stands for "`unsigned.`" The number after the `U` is the width of the
representation in bits, using the standard binary representation of an
unsigned integer.

* The names of the signed integer types are `I8`, `I16`, `I32`, and `I64`. The
`I` stands for "`[signed] integer.`" The number after the `I` is the width of 
the representation in bits, using the standard binary two's complement 
representation of a signed integer.

=== Floating-Point Type Names

The *floating-point type names* are `F32` and `F64`. These refer to the types
of IEEE
floating-point values of width 32 and 64 bits, respectively.

=== The Boolean Type Name

The type name `bool` represents the type of the two Boolean values `true` and
`false`.

=== String Type Names

A *string type name* consists of the keyword `string` optionally
followed by the keyword `size` and an
<<Expressions,_expression_>>. For example:
[source,fpp]
----
string
string size 256
----

The optional expression following the keyword `size` is called the *size
expression* of the string type name.  If present, it must have a
<<Types_Internal-Types_Numeric-Types,numeric type>>, and it must
evaluate to a value in the range [0,2^31^) after conversion to
<<Types_Internal-Types_Integer,_Integer_>>.

At each point in the model where a string type name appears, the following
<<Definitions-and-Uses_Implied-Uses,implied uses>> of 
<<Definitions_Framework-Definitions,framework definitions>> occur:

. Each string type name represents an implied use of the type
`FwSizeStoreType`.

. Each string type name that omits the `size` expression
represents an implied use of the constant
`FW_FIXED_LENGTH_STRING_SIZE`.

If the size expression is present, then it specifies the maximum
length of a string value represented by the type.
Otherwise, the maximum length is the value of
`FW_FIXED_LENGTH_STRING_SIZE`.

=== Qualified Identifier Type Names

A *qualified identifier type name* is a
<<Scoping-of-Names_Qualified-Identifiers,qualified
identifier>> that refers to an
<<Definitions_Abstract-Type-Definitions,abstract type definition>>,
<<Definitions_Alias-Type-Definitions,alias type definition>>,
<<Definitions_Array-Definitions,array definition>>,
<<Definitions_Enum-Definitions,enum definition>>,
<<Definitions_Struct-Definitions,struct definition>>,
or
<<Definitions,bound parameter definition>>
 via the
<<Scoping-of-Names_Resolution-of-Qualified-Identifiers,rules
for name scoping>>.
A qualified identifier type name _Q_ names a type as follows:

.  If _Q_ refers to a global definition _D_,
then _Q_ names the
<<Types,type>> defined in _D_.

.  Otherwise _Q_ refers to a bound parameter definition _B_.
In this case, _B_ must be a
<<Specifiers_Template-Expansion-Specifiers,type parameter definition>>.
Let _N_ be the type name appearing in the
<<Specifiers_Template-Expansion-Specifiers,type template argument>> of _B_.
Then _Q_ names the type named by _N_.
There are two cases:

.. If _N_ is a qualified identifier type name, then _B_
<<Definitions,represents>> a global definition _D_, and _Q_ names
the type defined in _D_.

.. Otherwise _N_ is a
<<Type-Names_Primitive-Integer-Type-Names,primitive integer type name>>, a
<<Type-Names_Floating-Point-Type-Names,floating-point type name>>,
<<Type-Names_The-Boolean-Type-Name,the Boolean type name>>, or a
<<Type-Names_String-Type-Names,string type name>>.
In this case _N_ refers to no definition. _Q_ names the type that _N_ names directly.

For example:

[source,fpp]
----
module M {
  type T
  array A = [3] T # T is a qualified identifier type name. It names the type M.T.
}
----

[source,fpp]
----
module M {
  array A = [3] U8
  array B = [3] A # A is an array type name. It names the type M.A.
}
----

[source,fpp]
----
module M {
  enum E { X = 0, Y = 1 }
  array A = [3] E # E is a qualified identifier type name. It names the type M.E.
}
----

[source,fpp]
----
module M {
  struct S {
    x: U32
    y: F32
  }
  struct T {
    s: S # S is a qualified identifier type name. It names the type M.S.
  }
}
----

[source,fpp]
----
module M {
  type T
  module template Tmpl(type X) {
    # X is a qualified identifier type name. It refers to the bound
    # parameter definition for the type parameter X.
    array A = [3] X
  }
}
module N {
  # X names the type M.T. The bound parameter definition represents
  # the global definition M.T.
  expand M.Tmpl(type M.T)
}
module P {
  # X names the type U32. The bound parameter definition represents
  # no global definition.
  expand M.Tmpl(type U32)
}
----

=== Range Type Names

A *range type name* represents a range of numeric values.

==== Syntax

<<Type-Names,_type-name_>> `in` _range_

* _range_ is _range-begin_ _range-bound_ `,` _range-bound_ _range-end_

* _range-begin_ is `(` or `[`

* _range-bound_ is an <<Expressions,expression>> or `--`

* _range-end_ is `)` or `]`

==== Semantics

A range type name _N_ names a <<Types_Range-Types,range type>> _T_
according to the following rules.

. _type-name_ must name a <<Types,type>> whose
  <<Types_Underlying-Types,underlying type>> _T'_ is a
  <<Types_Primitive-Numeric-Types,primitive numeric type>> or a
  <<Types_Range-Types,range type>>.

. Let _T''_ be the primitive numeric type defined as follows:

.. If _T'_ is a primitive numeric type, then let _T''_ be _T_.

.. Otherwise _T'_ is a range type _T'''_ `in` _range_, where
   _T'''_ is a primitive numeric type. In this case, let _T''_ be _T'''_.

. For each range bound _B_, if _B_ is an expression _e_, then _e_ must evaluate
  to a value that <<Evaluation_Strict-Type-Conversion,may be strictly converted 
  to a value of type _T''_>>.

. Let _T'''_ be the <<Types_Range-Types,range type>> _T''_ `in` _range_,
  where _range_ is constructed from the range in the type name by substituting
  each range bound _B_ that is an expression _e_ with the value
  produced by evaluating _e_ and converting the result to _T''_.  _T'''_ is the 
  type named by the range type name.  It must be a valid range type.

==== Examples

[source,fpp]
----
type T1 = U8 in [0, 10] # T1 represents U8 values v in the range 0 <= v <= 10
type T2 = U8 in (0, 10) # T2 represents U8 values v in the range 0 < v < 10
type T3 = U8 in [0, 10) # T3 represents U8 values v in the range 0 <= v < 10
type T4 = I16 in (--, 10) # T4 represents I16 values v in the range -32768 <= v < 10
type T5 = I16 in [--, 10) # T5 represents I16 values v in the range -32768 <= v < 10
type T6 = U16 in [0, --) # T6 represents U16 values v in the range 0 <= v <= 65535
type T7 = U16 in [0, --] # T7 represents U16 values v in the range 0 <= v <= 65535
type T8 = U16 in [--, --] # T8 represents all U16 values
type T9 = U8 in [0, 256] # T9 is invalid: 256 may not be strictly converted to U8
type T10 = U8 in [1, 0] # T10 is invalid: The specified range has no values
type T11 = F32 in [--, 10.5] # T11 represents all F32 values less than or equal to 10.5
type T12 = F32 in [--, 10.5) # T12 represents all F32 values less than 10.5
type T13 = T12 in [0, --] # T13 represents all F32 values v in the range 0 <= v < 10.5
type T14 = T13 in [0, 11] # T14 is invalid: 11 may not be strictly converted to T12
----
